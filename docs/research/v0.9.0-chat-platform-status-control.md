**Goal**: Extend Focally's current Slack integration to support these platforms.

## Discord

### API Availability
- **Base API**: Discord REST API
- **Endpoint**: `PATCH /users/@me` (Modify Current User)
- **Documentation**: https://discord.com/developers/docs/resources/user#modify-current-user

### Status Control
**Supported**: ✅ Partial
- Discord allows modifying user settings via `PATCH /users/@me`
- Custom status text can be set
- Presence status (online, idle, dnd, invisible) may be controllable

### Limitations
- Requires OAuth2 token (user token, not bot token)
- User tokens are **not officially supported** by Discord for third-party apps
- **Risk**: Discord may ban accounts using user tokens for automated status updates
- No official "Companion App" OAuth flow for status updates

### Authentication
```swift
// OAuth2 scopes required (if official support existed)
scopes: [
    "identify",           // Basic user info
    "presence.update",    // Update user presence (likely)
    "activities.write",   // Update custom status (likely)
]
```

### Implementation Complexity
**High** - Due to OAuth2 user token restrictions and policy violations.

### Recommendation
❌ **Not recommended for production**
- Discord actively discourages user token automation
- Alternative: Consider Discord Rich Presence (shows activity, not status)
- Better: Focus on Slack, Teams, Zoom which have official APIs

## Microsoft Teams

### API Availability
- **Base API**: Microsoft Graph API v1.0
- **Endpoint**: `POST /users/{id}/presence/setPresence`
- **Documentation**: https://learn.microsoft.com/en-us/graph/api/presence-setpresence

### Status Control
**Supported**: ✅ Full

#### Request Format
```http
POST https://graph.microsoft.com/v1.0/users/{user-id}/presence/setPresence
Content-Type: application/json

{
  "sessionId": "22553876-f5ab-4529-bffb-cfe50aa89487",
  "activity": "Busy",
  "availability": "Busy",
  "expirationDuration": "PT1H"
}
```

#### Activity Values
- `Available` (Green)
- `Busy` (Red)
- `DoNotDisturb` (Red)
- `Away` (Yellow)
- `Offline` (Gray)
- `InACall`
- `InAConferenceCall`
- `InAMeeting`
- `Presenting`
- `Unknown`

#### Availability Values
- `Available`
- `AvailableIdle`
- `Away`
- `BeRightBack`
- `Busy`
- `BusyIdle`
- `DoNotDisturb`
- `Offline`
- `PresenceUnknown`

### DND Control
**Supported**: ✅
- Set activity to `"DoNotDisturb"`
- Set availability to `"DoNotDisturb"`
- Optional `expirationDuration` for auto-revert

### Authentication
```swift
// Microsoft Entra ID (formerly Azure AD) OAuth2
scopes: [
    "Presence.ReadWrite.All",  // Set presence for all users
    "User.Read.All",           // Read user info
]

// Alternative (delegated permissions for personal app)
scopes: [
    "Presence.ReadWrite",  // Set own presence
    "User.Read",
]
```

### Token Management
- OAuth2 flow with PKCE (for desktop apps)
- Refresh tokens for long-lived access
- Token storage in Keychain (same pattern as SlackService)

### Implementation Complexity
**Medium** - Similar to Slack integration.

### Sample Implementation Pattern
```swift
class TeamsService {
    private let setPresenceURL = URL(string: "https://graph.microsoft.com/v1.0/me/presence/setPresence")!
    private let keychainKey = "teams-token"

    func setPresence(activity: String, availability: String, duration: TimeInterval) async {
        guard let token = token else { return }

        let body: [String: Any] = [
            "sessionId": UUID().uuidString,
            "activity": activity,
            "availability": availability,
            "expirationDuration": ISO8601DurationString(seconds: duration)
        ]

        let request = createGraphRequest(url: setPresenceURL, token: token, body: body)
        await performRequest(request)
    }
}
```

### Recommendation
✅ **Highly recommended** - Official API, well-documented, similar complexity to Slack.

## Zoom

### API Availability
- **Base API**: Zoom REST API
- **Endpoint**: `PUT /accounts/{accountId}/users/{userId}/status`
- **Documentation**: https://developers.zoom.us/docs/api/rest/reference/user/methods/
- **Scope**: `contact_center:write:batch_users:admin`

### Status Control
**Supported**: ✅ Limited

#### Request Format
```http
PUT https://api.zoom.us/v2/accounts/{accountId}/users/{userId}/status
Authorization: Bearer {token}
Content-Type: application/json

{
  "action": "activate"
}
```

**Note**: This appears to be for Zoom Contact Center, not standard Zoom Chat.

### Limitations
- Zoom's status API is primarily for Contact Center (enterprise)
- Standard Zoom Chat/Meetings status may not be programmatically controllable
- Requires Account ID + User ID lookup

### DND Control
**Supported**: ❌ Unclear
- No direct "DND" API found in standard Zoom API
- Focus status may be controlled via user settings endpoint

### Authentication
```swift
// Zoom OAuth2
scopes: [
    "user:write:admin",      // Write user settings
    "user:update:settings:admin",  // Update user settings
]

// For personal app (delegated)
scopes: [
    "user:write",
    "user:update:settings",
]
```

### Implementation Complexity
**High** - Limited API, unclear enterprise/consumer distinction.

### Recommendation
⚠️ **Conditional** - Investigate further for standard Zoom Chat/Meetings status control.

## Implementation Notes

### Token Storage
- Use `KeychainHelper` (same as SlackService)
- Store OAuth2 tokens securely

### Rate Limiting
- **Teams**: Graph API has rate limits (similar to Slack)
- **Zoom**: API rate limits apply (tiered by plan)

### Error Handling
- Network errors
- Token expiration (use refresh tokens)
- Rate limit responses (429)
- Invalid scope/permission errors

## Risks & Mitigations

### Microsoft Teams
- **Risk**: Graph API rate limits
- **Mitigation**: Implement exponential backoff, cache presence updates

### Zoom
- **Risk**: API may be enterprise-only
- **Mitigation**: Validate with personal Zoom account first

### Discord
- **Risk**: Account ban for user token automation
- **Mitigation**: **Do not implement** - Discord policy violation
