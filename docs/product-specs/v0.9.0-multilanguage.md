# Focally v0.9.0 - Multi-language Support (EN/ES/PT)

## Overview

Add comprehensive multi-language support for English, Spanish, and Portuguese with automatic system language detection and manual override.

---

## Goals

1. **Auto-detection**: Detect system language on app launch and default to EN/ES/PT
2. **Manual Override**: Allow users to manually change language in settings
3. **Complete Translation**: Translate all user-facing strings to EN/ES/PT
4. **Persist Preference**: Save language choice to UserDefaults
5. **Runtime Switching**: Update UI immediately when language changes

---

## Non-Goals

- Right-to-left (RTL) language support
- Dynamic translation loading from external files
- Translation of code comments or internal logs
- Automatic translation API integration

---

## Requirements

### Functional

**FR-1 Auto-Detection**
- On app launch, detect system language via `Locale.current.language.languageCode`
- Default to English if system language is not EN/ES/PT
- Check UserDefaults for manual override first
- Support: `["en", "es", "pt"]`

**FR-2 Manual Override**
- Add language selection UI in Settings
- Show current language with checkmark
- Persist choice to `focally.language` in UserDefaults
- Apply change immediately (no app restart required)

**FR-3 Localization System**
- Use SwiftUI's native `String(localized:)` API
- Create `Localizable.strings` files for EN/ES/PT
- Organize resource folders: `Focally/Resources/{en,es,pt}.lproj/`
- Update `project.yml` to include resource files

**FR-4 Complete Translation**
- Translate all hardcoded strings in:
  - `FocusSetupView.swift` (~12 strings)
  - `IntegrationsSettingsView.swift` (~20 strings)
  - `GeneralSettingsView.swift` (~15 strings)
  - `AboutSettingsView.swift` (~10 strings)
  - `TimerPage.swift` (~10 strings)
  - `SidebarView.swift` (~8 strings)
  - `MainWindow.swift` (~5 strings)
  - `FocusModeEditSheet.swift` (~15 strings)
  - `AppSettingsSheet.swift` (~10 strings)
- Total estimated: ~105 strings

**FR-5 Locale Environment Injection**
- Inject `\.locale` environment variable at app root
- Use `Locale(identifier:)` with `appLanguage.currentLanguage`
- Update environment when language changes via `AppLanguage.setLanguage()`

### Non-Functional

**NFR-1 Performance**
- Language detection must complete on app launch (<100ms)
- String lookups must be cached by SwiftUI
- No network requests for localization

**NFR-2 Maintainability**
- All translations in single `Localizable.strings` per language
- Comments for context in translation files
- Consistent naming convention: `section_element_name`

**NFR-3 Testing**
- Verify all translated strings render correctly
- Test language switching without app restart
- Verify system language detection edge cases

## Architecture

### Files

**New Files**
- `Focally/Resources/en.lproj/Localizable.strings`
- `Focally/Resources/es.lproj/Localizable.strings`
- `Focally/Resources/pt.lproj/Localizable.strings`
- `Focally/Models/AppLanguage.swift` (language management service)
- `Focally/Views/Settings/LanguageSettingsView.swift` (UI for language selection)

**Modified Files**
- `Focally/project.yml` (add resource folders)
- `Focally/OnItFocusApp.swift` (inject locale environment)
- `Focally/Views/Settings/SettingsPage.swift` (add Language subpage)
- All View files with hardcoded strings (~15 files)

### Data Flow

```
App Launch
  ├─ Check UserDefaults for manual override
  ├─ Check system language via Locale.current
  ├─ Fallback to English if unsupported
  └─ Set appLanguage.currentLanguage

Settings → Language Selection
  ├─ User selects ES/PT/EN
  ├─ Call appLanguage.setLanguage(code)
  ├─ Persist to UserDefaults
  └─ SwiftUI environment updates automatically

String Rendering
  ├─ View uses Text("key", comment: "context")
  ├─ SwiftUI looks up in .lproj/Localizable.strings
  └─ Returns translated string based on current locale
```

- `setup_subtitle` → "Focus timer with..."

- `settings_general` → "General"

1. **Extraction**: Scan all View files for hardcoded strings

## Edge Cases

**EC-1 Unsupported System Language**
- System language: French (`fr`)
- Expected: Default to English (`en`)

**EC-2 Empty UserDefaults**
- First app launch, no manual override
- Expected: Use system language detection

**EC-3 Manual Override Persistence**
- User selects ES, closes app, reopens
- Expected: App loads in ES (saved in UserDefaults)

**EC-4 Invalid Language Code**
- UserDefaults contains corrupted language code
- Expected: Fallback to English, reset UserDefaults

---

## Risks & Mitigations

**R1 Missing Translations**
- Risk: Keys missing from `Localizable.strings`
- Mitigation: Build-time warning; fail build on missing keys

**R2 Context Loss in Translation**
- Risk: Strings translated incorrectly without context
- Mitigation: Use `comment` parameter in `String(localized:)` calls

**R3 Runtime Performance**
- Risk: Slow string lookups
- Mitigation: SwiftUI caches translations; no network calls
