# Spec: v0.9.3 Language Picker Root Cause Fix

## Context
Language picker fix in v0.9.2 added `.environment(\.locale, appLanguage.locale)` to MainWindow, BUT this doesn't work.

## Root Cause (The Real Bug)

**SwiftUI's `String(localized:)` and `LocalizedStringResource` ignore `.environment(\.locale)` in macOS.**

From `AppLanguage.swift` comment:
```swift
/// `String(localized:)` and `LocalizedStringResource` resolve against
/// `Bundle.main.preferredLocalizations` (the OS language), ignoring
/// SwiftUI's `\\.locale` environment.
```

**Why it doesn't work**:
- `.environment(\.locale, appLanguage.locale)` affects date formatters, NOT string localization
- `String(localized: "key")` uses `Bundle.main.preferredLocalizations` (system locale)
- To override language, must use `appLanguage.localizedString(_:)` which loads from specific `.lproj` bundle

## The Fix Required

**Replace ALL `String(localized:)` and `LocalizedStringResource` usage with `appLanguage.localizedString(_:)`**

### Pattern 1: String(localized:) → appLanguage.localizedString(_:)

**Before**:
```swift
Text(String(localized: "tab_timer"))
```

**After**:
```swift
@Environment(AppLanguage.self) private var appLanguage
Text(appLanguage.localizedString("tab_timer"))
```

### Pattern 2: LocalizedStringResource → appLanguage.localizedString(_:)

**Before**:
```swift
static var title: LocalizedStringResource = "Start Focus"
Button(String(localized: FocusIntegrationAction.start.title))
```

**After**:
```swift
static var title: String = "start_focus_action"  // Use key string
Button(appLanguage.localizedString(FocusIntegrationAction.start.title))
```

### Pattern 3: String(localized: LocalizedStringResource(stringLiteral: key)) → appLanguage.localizedString(_:)

**Before**:
```swift
Text(String(localized: LocalizedStringResource(stringLiteral: "metrics_tab")))
```

**After**:
```swift
@Environment(AppLanguage.self) private var appLanguage
Text(appLanguage.localizedString("metrics_tab"))
```
